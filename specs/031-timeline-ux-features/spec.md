## User Scenarios & Testing *(mandatory)*

### User Story 1 — ランダムタイムライン (Priority: P1)

ユーザーがタイムラインの表示順を「ランダム」に切り替えると、投稿が有効期限内の投稿群からランダムにサンプリングされて表示される。「最新投稿が常に上に来て目立つ」という計算を成立させない。

**Why this priority**: フィード体験の根幹に関わり、「新着順」によるゲーミング（狙い打ち投稿）を排除する最重要機能。

**Independent Test**: タイムライン上の「ランダム」ボタンを押して数回リロードし、順序が毎回変わることを確認する。

**Acceptance Scenarios**:

1. **Given** タイムラインが表示されている, **When** ユーザーが「ランダム」フィルターを選択する, **Then** 投稿の表示順が毎回異なり、最新日時順ではなくなる
2. **Given** 「ランダム」モードが選択されている, **When** タイムラインを再読み込みする, **Then** 前回と異なる順序で投稿が並ぶ（同一順序になる確率は統計的に極めて低い）
3. **Given** 「ランダム」モードで「もっと見る」を押す, **When** 追加投稿が読み込まれる, **Then** 追加分もランダム順で末尾に追加される
4. **Given** 他のフィルター（まもなく消える 等）との併用, **When** ランダムモードで残り時間フィルターを適用する, **Then** 残り時間条件を満たした投稿の中でランダムに並ぶ

---

### User Story 2 — アクティブ投稿数バナー (Priority: P2)

タイムライン上部に「今 N 件の言葉が生きています」と現在アクティブな投稿総数をひっそり表示する。個々の投稿への承認欲求ではなく、今この瞬間に存在する言葉の全体量を感じさせる。

**Why this priority**: 実装コストが極めて小さく、サービスの「生きている感」を演出する効果が高い。

**Independent Test**: 投稿が存在する状態でタイムラインを開き、バナーに件数が表示されていることを確認する。

**Acceptance Scenarios**:

1. **Given** アクティブな投稿が存在する, **When** タイムラインを開く, **Then** 「今 N 件の言葉が生きています」という件数バナーが表示される
2. **Given** アクティブな投稿が 0 件, **When** タイムラインを開く, **Then** バナーは表示されないか「0件」を表示しない（静寂表示と整合）
3. **Given** バナーが表示されている, **When** 投稿が期限切れで消える, **Then** 次回のタイムライン更新（ポーリング）後に件数が更新される

---

### User Story 3 — 深夜タイムライン（夜の寝言フィルター）(Priority: P2)

22:00〜翌 5:00 JST に投稿された投稿のみを表示するフィルターモード「夜の寝言」をタイムラインに追加する。昼間のパフォーマンス的な投稿より、深夜の本音に近い声を選んで読める。

**Why this priority**: 既存フィルター UI への追加のみで実装でき、サービスの哲学を体験的に強化する。

**Independent Test**: 「夜の寝言」フィルターを選択し、深夜帯以外に投稿されたものが除外されることを確認する。

**Acceptance Scenarios**:

1. **Given** 深夜帯・昼間帯の投稿が混在している, **When** 「夜の寝言」フィルターを選択する, **Then** 22:00〜翌5:00 JST に投稿されたもののみが表示される
2. **Given** 「夜の寝言」フィルターが選択されている, **When** 該当投稿が 0 件の場合, **Then** 「このフィルターに該当する投稿がありません」が表示される
3. **Given** JST 22:00 ちょうどに投稿された投稿, **When** 「夜の寝言」フィルターを選択する, **Then** その投稿は表示される（境界値: 22:00 以上 5:00 未満）

### User Story 4 — ブラインドポスト（本人識別禁止）(Priority: P3)

タイムライン上で自分の投稿が他ユーザーの投稿と完全に同じスタイルで表示され、「これが自分の投稿」という識別マークが一切存在しない。「自分の投稿への反応を確認する」ループを断つ。

**Why this priority**: 現在の実装がすでに識別マークなしに近いが、設計上の明示的な禁止として確立する。

**Independent Test**: 自分が投稿した直後にタイムラインを表示し、自分の投稿が他の投稿と視覚的に区別できないことを確認する。

**Acceptance Scenarios**:

1. **Given** ユーザーが投稿した後, **When** タイムラインを表示する, **Then** 自分の投稿と他の投稿の見た目（スタイル・マーク・ラベル）が完全に同一である
2. **Given** ログイン済みユーザーのタイムライン表示, **When** 自分の投稿が表示されている, **Then** 「自分の投稿」を示すバッジ・ボーダー・テキスト・色変化が一切ない
3. **Given** ゲストユーザーとログイン済みユーザーが同じ投稿を見る, **When** タイムラインを比較する, **Then** 投稿カードの見た目に差異がない

---

### User Story 5 — 消えかけ投稿のゆらぎアニメーション (Priority: P3)

残り時間が 5 分以内になった投稿のテキストに微細な揺らぎアニメーションを加える。数値ではなく物理的な揺らぎで「もうすぐ消える」という儚さを表現する。

**Why this priority**: 視覚的な演出であり他機能への影響がない。残り時間カウントダウンを補完する体験強化。

**Independent Test**: 残り時間が 5 分以内の投稿カードのテキストに揺らぎアニメーションが適用されていることを確認する。

**Acceptance Scenarios**:

1. **Given** 残り時間が 5 分超の投稿, **When** タイムラインを表示する, **Then** テキストに揺らぎアニメーションは適用されない
2. **Given** 残り時間が 5 分以内になった投稿, **When** タイムラインを表示する（またはリアルタイムで閾値を越えた時）, **Then** テキストに微細な揺らぎアニメーションが適用される
3. **Given** カウントダウン非表示モードが有効な場合, **When** 残り 5 分を切った投稿を表示する, **Then** 揺らぎアニメーションは依然として適用される（時間概念を視覚的に残す）

---

### Edge Cases

- 「ランダム」モードで投稿が 0 件または 1 件の場合は順序変化なし
- 深夜フィルターの時刻判定は投稿者のローカル時刻ではなく投稿レコードの `createdAt`（JST変換後）を使用する
- 揺らぎアニメーションはカウントダウン非表示モードでも動作する（アニメーション自体は `remaining` の値で制御）
- ブラインドポストの「識別禁止」はマイポストページには適用しない（自分の投稿一覧は別文脈）
- アクティブ投稿数バナーの件数はフィルターに依らず全アクティブ件数を表示する

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: タイムラインは「ランダム」表示順モードを提供し、リクエスト毎に異なる順序で有効投稿を返す
- **FR-002**: 「ランダム」モードは既存フィルター（残り時間フィルター）と併用できる
- **FR-003**: 「ランダム」モードでの「もっと見る」（ページネーション）は引き続き動作する
- **FR-004**: タイムライン上部にアクティブ投稿の総件数を表示するバナーを設ける
- **FR-005**: アクティブ件数バナーはポーリング更新のタイミングで最新値に反映される
- **FR-006**: タイムラインフィルターに「夜の寝言」モードを追加し、JST 22:00〜翌5:00 に投稿されたもののみ表示する
- **FR-007**: 深夜フィルターの時刻判定は投稿の `createdAt` を JST に変換した時（hour）で判定する
- **FR-008**: タイムライン上の投稿カードはログインユーザーの投稿であっても他の投稿と視覚的に区別されない
- **FR-009**: 投稿カードに「自分の投稿」を示す視覚要素（バッジ・色変化・ラベル等）を追加してはならない
- **FR-010**: 残り時間が 5 分（300 秒）以内の投稿テキストに揺らぎ CSS アニメーションを適用する
- **FR-011**: 揺らぎアニメーションは残り時間が 5 分を超えた投稿には適用されない
- **FR-012**: 揺らぎアニメーションはカウントダウン非表示モードの有無に関わらず機能する

### Key Entities

- **タイムラインフィルター**: 表示順（新着順/ランダム）と時間帯（全件/夜の寝言）の組み合わせを定義する概念
- **アクティブ投稿数**: 現時点で `hiddenAt > NOW()` かつ削除されていない投稿の総件数
- **残り時間閾値**: 揺らぎアニメーションが開始される残り時間（300 秒 = 5 分）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 「ランダム」モードを 5 回連続でリロードしたとき、少なくとも 2 回は異なる順序で投稿が並ぶ
- **SC-002**: アクティブ投稿数バナーに表示される件数が、実際のアクティブ投稿数と常に一致する（ポーリング更新後）
- **SC-003**: 「夜の寝言」フィルター適用時、22:00〜5:00 JST 以外に投稿された投稿が 0 件も表示されない
- **SC-004**: 残り 5 分以内の投稿に揺らぎアニメーションが視認でき、5 分超の投稿には適用されない
- **SC-005**: ログイン済みユーザーのタイムラインで自分の投稿と他ユーザーの投稿の見た目に差異がない（目視確認）

## Assumptions

- ランダム順はサーバー側でのランダムサンプリングで実現する（クライアント側のシャッフルではなく）
- アクティブ投稿数はタイムラインの API レスポンスに含める（別 API エンドポイントは作らない）
- 深夜フィルターの時刻は `createdAt` をJST変換して判定する（ `hiddenAt` 基準ではない）
- ブラインドポストは新規実装不要（現在の実装が既にログインユーザーの投稿を識別していない）。設計上の明示的な確認として検証のみ行う
- 揺らぎアニメーションは `CountdownTimer` が管理する残り時間（`remaining` ミリ秒）を PostCard に渡すことで実現する
- ランダムモードでのカーソルページネーションは「次の 20 件をランダムに取得」として実装する（同一投稿の重複が起きうるが許容する）
- マイポストページは本スペックの対象外（ブラインドポストの識別禁止はタイムラインのみに適用）

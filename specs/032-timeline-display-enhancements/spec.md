## User Scenarios & Testing *(mandatory)*

### User Story 1 — 自動スクロールモード B-2 (Priority: P2)

ユーザーがタイムラインの「自動スクロール」モードをオンにすると、ページが操作なしにゆっくりと下へ流れ続ける。映画のエンドロールのように言葉が流れてくる状態で読める。

**Why this priority**: タイムライン体験を受動的にすることで「何を読もうか」という能動的な選択コストをなくす。実装コストが小さく体験価値が高い。

**Independent Test**: タイムラインの自動スクロールボタンをオンにして何も操作せずに放置し、画面が自動で下に流れることを確認する。

**Acceptance Scenarios**:

1. **Given** タイムラインが表示されている, **When** ユーザーが自動スクロールボタンをオンにする, **Then** ページが自動的に一定速度で下に流れ始める
2. **Given** 自動スクロールが動作中, **When** ユーザーがスクロールを手動操作する, **Then** 自動スクロールが停止し手動操作が優先される
3. **Given** 自動スクロールが動作中, **When** オフボタンを押す, **Then** 自動スクロールが止まりページ位置はそのまま保持される
4. **Given** ユーザーが `prefers-reduced-motion` を設定している, **When** 自動スクロールをオンにしようとする, **Then** 自動スクロールは起動しない（アクセシビリティ尊重）
5. **Given** 自動スクロールがオンの状態でページを閉じた, **When** 次回タイムラインを開く, **Then** 自動スクロールはオフの状態で開始される（セッション限定）

### User Story 2 — 消えた言葉の気配バナー B-4 (Priority: P2)

タイムラインの末尾に「今日、N 件の言葉がここを旅立った」という一文がひっそり表示される。消えた投稿の件数を追悼として見せる。

**Why this priority**: 実装コストが小さく、サービスの「消えていく」哲学を体感させる演出効果が高い。

**Independent Test**: 投稿が期限切れになった状態でタイムラインを開き、末尾に今日消えた件数が表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 当日中に有効期限が切れた投稿が存在する, **When** タイムラインを開く, **Then** 末尾に「今日、N 件の言葉がここを旅立った」が表示される
2. **Given** 当日消えた投稿が 0 件, **When** タイムラインを開く, **Then** 気配バナーは表示されない
3. **Given** 気配バナーが表示されている, **When** 30 秒ポーリングで更新が走る, **Then** バナーの件数も最新値に更新される

---

### User Story 3 — 文字数連動フォントサイズ B-8 (Priority: P3)

投稿カードの本文フォントサイズが投稿の文字数によって変わる。短い言葉は大きく、長い文章は小さく表示される。

**Why this priority**: 視覚的な演出で一言の重さを際立てる。実装コストが極小で他機能への影響がない。

**Independent Test**: 異なる文字数の投稿が並ぶタイムラインを開き、文字数が少ない投稿のフォントが大きく表示されることを目視確認する。

**Acceptance Scenarios**:

1. **Given** 文字数が少ない投稿（〜30文字）, **When** タイムラインに表示する, **Then** 大きいフォントサイズ（lg以上相当）で表示される
2. **Given** 文字数が多い投稿（151〜255文字）, **When** タイムラインに表示する, **Then** 小さいフォントサイズ（sm相当）で表示される
3. **Given** 同じタイムライン上に短い投稿と長い投稿が混在している, **When** 表示を確認する, **Then** 文字数に応じて明らかにフォントサイズが異なる

---

### User Story 4 — カラーモード 3 択 B-9 (Priority: P3)

ユーザーが色表示モードを「ノーマル」「モノクロ」「セピア」の 3 択から選べる。設定は次回起動時も保持される。

**Why this priority**: 既存のモノクロモードを拡張するだけで実装できる。色の刺激をさらに選択的に制御できる。

**Independent Test**: 設定でセピアモードを選択し、タイムラインがセピア調で表示され、再起動後もセピアモードが維持されることを確認する。

**Acceptance Scenarios**:

1. **Given** ユーザーがカラーモード設定を開く, **When** 「セピア」を選択する, **Then** タイムラインがセピアトーンで表示される
2. **Given** セピアモードが選択されている, **When** ページを閉じて再度開く, **Then** セピアモードが保持されている
3. **Given** モノクロモードが有効, **When** 「ノーマル」に切り替える, **Then** 通常のカラー表示に戻る
4. **Given** 3 択が並ぶ, **When** それぞれを選択する, **Then** ノーマル・モノクロ・セピアが視覚的に明確に異なる

---

### User Story 5 — 深夜フォントウェイト B-10 (Priority: P3)

JST 22:00〜翌 5:00 の深夜帯はタイムライン全体のフォントウェイトが細く（light）なる。昼間と夜間で読む感触が変わる。

**Why this priority**: 既存の深夜フィルターと思想を共有し、実装コストが極小。時間連動の体験を追加する。

**Independent Test**: 深夜帯（JST 22:00〜5:00）にタイムラインを開き、フォントが細くなっていることを目視確認する。または時刻をモックして確認する。

**Acceptance Scenarios**:

1. **Given** JST 22:00〜翌 5:00 の深夜帯, **When** タイムラインを表示する, **Then** タイムライン本文のフォントウェイトが細く（light）なっている
2. **Given** JST 5:00〜22:00 の昼間帯, **When** タイムラインを表示する, **Then** タイムライン本文のフォントウェイトは通常（normal）
3. **Given** 深夜フォントが適用されている状態, **When** 22:00-5:00 の時間帯境界を越える, **Then** フォントウェイトが次のページ読み込み時（またはポーリング後）に更新される

---

### User Story 6 — 投稿時間帯ヒートマップ B-11 (Priority: P3)

ログイン済みユーザーがマイページを開くと、自分の投稿を時間帯別（0〜23時）で視覚化したグラフを見られる。件数ではなく「いつ書いてきたか」のパターンを確認できる。

**Why this priority**: 自己観察の道具として機能する。承認欲求（何件読まれたか）ではなく自分の習慣を知る機能。

**Independent Test**: 異なる時間帯に投稿した履歴があるユーザーのマイページを開き、各時間帯の投稿パターンが棒グラフで表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** ログイン済みユーザーがマイページを開く, **When** ヒートマップセクションを確認する, **Then** 0〜23時の時間軸で自分の投稿パターンが表示される
2. **Given** ヒートマップが表示されている, **When** グラフを確認する, **Then** 縦軸には投稿件数の具体的な数値は表示されず、相対的な高さのみで比較できる
3. **Given** 投稿履歴がゼロのユーザー, **When** マイページを開く, **Then** ヒートマップは表示されないか「まだ投稿がありません」と表示される
4. **Given** ヒートマップが表示されている, **When** グラフを確認する, **Then** ログインしていない第三者には見えない（本人専用）

---

### User Story 7 — 書く前に読む B-12 (Priority: P3)

ログイン済みユーザーが投稿フォームを開くと、自分の過去の投稿（すでに消えたもの）がランダムに 1 件、フォームの上部に薄く表示される。

**Why this priority**: 「今日も書く前に、かつての自分の言葉に出会う」という体験を作る。承認欲求ではなく自己との対話を促す。

**Independent Test**: 過去に投稿して期限切れになった投稿があるユーザーとして投稿フォームを開き、フォーム上部に過去の投稿が薄く表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 過去に投稿して期限切れになった投稿があるユーザーが投稿フォームを開く, **When** フォームが表示される, **Then** 過去の投稿（消えたもの）が 1 件ランダムにフォーム上部に薄く表示される
2. **Given** 過去の投稿がゼロのユーザーが投稿フォームを開く, **When** フォームが表示される, **Then** 過去投稿エリアは表示されない
3. **Given** 過去投稿がフォーム上部に表示されている, **When** ユーザーが投稿文を入力する, **Then** 過去投稿表示は邪魔にならず、投稿フォームの操作に支障がない
4. **Given** ゲストユーザーが投稿フォームを開く, **When** フォームが表示される, **Then** 過去投稿エリアは表示されない（ゲストには投稿履歴がない）

---

### Edge Cases

- 自動スクロールはページ末尾に達したら静かに停止する。「もっと見る」はユーザーが手動で押す（自動発火しない）
- 文字数フォントサイズの閾値は 30 / 80 / 150 文字の 4 段階（30 以下: XL、31-80: L、81-150: M、151 以上: S）
- ヒートマップのデータは JST 変換後の時刻で集計する
- カラーモード（B-9）とモノクロモード（既存）が競合しないよう、カラーモードが既存設定を統合する
- 書く前に読む（B-12）の過去投稿は論理削除済みのものは除外する（`deleted_at IS NOT NULL` は除く）
- 深夜フォント（B-10）の時刻判定はクライアント側の現在時刻で行う（サーバー判定不要）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: タイムラインに自動スクロールのオン/オフボタンを設ける
- **FR-002**: 自動スクロールは `prefers-reduced-motion` が設定されている場合は動作しない
- **FR-003**: 自動スクロール中にユーザーが手動スクロールした場合は自動スクロールを停止する
- **FR-004**: タイムライン末尾に当日消滅した投稿の件数を「今日、N 件の言葉がここを旅立った」として表示する
- **FR-005**: 当日消滅件数が 0 件の場合、気配バナーは表示しない
- **FR-006**: 投稿カードの本文フォントサイズを文字数に応じて 4 段階で変える（30 文字以下 / 31-80 / 81-150 / 151 以上）
- **FR-007**: カラーモード設定を「ノーマル」「モノクロ」「セピア」の 3 択にする（既存モノクロオプションを統合）
- **FR-008**: カラーモードの選択は永続化し（localStorage）次回起動時も保持する
- **FR-009**: JST 22:00〜翌 5:00 の深夜帯はタイムライン本文のフォントウェイトを `font-light` に変更する
- **FR-010**: 深夜フォントの時刻判定はクライアントの現地時刻（JST 変換後）で行う
- **FR-011**: マイページにログイン済みユーザー専用の投稿時間帯ヒートマップを表示する
- **FR-012**: ヒートマップの縦軸は投稿件数の実数値を表示せず、最多投稿数の時間帯を 100% として他の時間帯をその比率でバー高さを決める
- **FR-013**: 投稿フォームを開いたとき、過去の消えた自分の投稿（期限切れ・論理削除なし）から 1 件ランダムに選んでフォーム上部に薄く表示する
- **FR-014**: 過去投稿がない場合（または未ログインの場合）、書く前に読むエリアは非表示にする

### Key Entities

- **カラーモード**: "normal" | "grayscale" | "sepia" の 3 値を取るユーザー設定。localStorage に保存
- **消滅件数 (expiredToday)**: 当日 JST 0:00〜現在までに `hidden_at` を過ぎた投稿の件数
- **投稿時間帯分布**: 0〜23 時のバケツごとの投稿数を持つ配列（JST 変換済み）
- **過去の消えた投稿**: `hidden_at <= NOW()` かつ `deleted_at IS NULL` のユーザー自身の投稿

---

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 自動スクロールモードをオンにしてから 1 秒以内にスクロールが開始される
- **SC-002**: 手動スクロール操作から 0.5 秒以内に自動スクロールが停止する
- **SC-003**: 消えた件数バナーに表示される数値が実際の当日消滅件数と一致する（ポーリング更新後）
- **SC-004**: ヒートマップに表示される時間帯が、実際の投稿の JST 投稿時刻と一致する
- **SC-005**: 書く前に読む機能が、過去の消えた投稿がある場合に 100% の確率で何かを表示する
- **SC-006**: カラーモード切替から 200ms 以内に画面全体の色調が変わる

## Clarifications

### Session 2026-06-28

- Q: 自動スクロール（B-2）がタイムライン末尾に達したとき、どのように振る舞うか？ → A: 末尾で静かに停止する。「もっと見る」ボタンは通常通りユーザーが手動で操作する（自動ページロードなし）
- Q: B-9 カラーモードの localStorage キーと既存モノクロ設定の移行方法は？ → A: 新キー `negotole_color_mode`（値: "normal"/"grayscale"/"sepia"）を導入し、起動時に旧キー `negotole_grayscale` が "true" なら "grayscale" に変換して旧キーを削除する
- Q: B-11 投稿時間帯ヒートマップの縦軸（バー高さ）の正規化方法は？ → A: 最多投稿数の時間帯を 100% として、他の時間帯をその比率（0〜100%）でバー高さを決める

## Assumptions

- 自動スクロールのデフォルト速度は 30px/秒固定（ユーザー調整不可。v1）
- 自動スクロールはセッション非永続（localStorage に保存しない。ページを開くたびにオフ）
- カラーモードは新キー `negotole_color_mode`（値: "normal" / "grayscale" / "sepia"）を使用する。初回起動時に旧キー `negotole_grayscale` が `"true"` であれば `"grayscale"` に変換して新キーへ移行し、旧キーを削除する
- ヒートマップは `マイページ` 内の新しいセクションとして追加する
- ヒートマップのデータは毎回マイページ表示時に取得する（キャッシュなし。v1）
- 書く前に読む（B-12）は `PostForm` が表示される `/post` ページでのみ動作する
- 過去投稿の取得件数は最大 100 件からランダム 1 件選択（サーバー側でランダム取得）
- 文字数フォントサイズの適用対象は `PostCard` の本文テキストのみ（タイトルや残り時間表示には適用しない）

# Feature Specification: 管理者用アカウント凍結機能

**Feature Branch**: `020-admin-account-freeze`

**Created**: 2026-06-07

**Status**: Draft

**Input**: User description: "docs/claude_todo.md の管理者用アカウント凍結機能を実装して"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理者がアカウントを凍結する (Priority: P1)

管理者が問題のある行動を取ったユーザーのアカウントを即座に停止できる。管理者は管理画面からユーザーを特定し、凍結理由を入力して凍結を実行する。凍結されたユーザーはただちにシステムへのアクセスを失う。

**Why this priority**: 不適切なコンテンツの投稿や嫌がらせ行為に対して即座に対処できることが、サービスの安全性を担保する最重要機能。

**Independent Test**: 管理画面でユーザーを凍結し、そのユーザーのセッションが無効化されてログインもできなくなることを確認する。

**Acceptance Scenarios**:

1. **Given** 管理者がログイン済み、**When** 管理画面でユーザーを選択して「凍結」を実行する、**Then** 対象ユーザーのアカウントが即座に凍結され、凍結理由と実施日時が記録される
2. **Given** ユーザーがログイン中、**When** 管理者がそのユーザーを凍結する、**Then** 凍結後の次のアクセス時にユーザーはログイン不可状態になる
3. **Given** 凍結済みユーザー、**When** ログインを試みる、**Then** 「アカウントが停止されています」旨のメッセージが表示されてログインを拒否される

---

### User Story 2 - 管理者が凍結を解除する (Priority: P2)

誤凍結や問題が解決したケースで、管理者がアカウント凍結を解除し、ユーザーが再びサービスを利用できるようにする。

**Why this priority**: 凍結機能を安全に運用するには、解除機能も必須。誤凍結の救済手段がないと運用リスクが高い。

**Independent Test**: 凍結済みのアカウントを管理画面で解除し、そのユーザーが再度ログインできることを確認する。

**Acceptance Scenarios**:

1. **Given** 凍結済みユーザーが存在する、**When** 管理者が管理画面で「凍結解除」を実行する、**Then** アカウントが有効化され解除日時が記録される
2. **Given** 凍結解除されたユーザー、**When** ログインを試みる、**Then** 通常通りログインできる

---

### User Story 3 - 管理者が凍結済みアカウントを一覧確認する (Priority: P3)

管理者が現在凍結中のアカウントをすべて把握し、各凍結の理由・日時・実施者を確認できる。

**Why this priority**: 凍結状況の把握は運用上重要だが、凍結・解除機能の後続として実装できる。

**Independent Test**: 管理画面の凍結一覧に凍結済みユーザーが表示され、理由・日時が確認できることを検証する。

**Acceptance Scenarios**:

1. **Given** 複数の凍結済みユーザーが存在する、**When** 管理者が凍結一覧を開く、**Then** 凍結中のユーザー名・凍結理由・凍結日時が一覧表示される
2. **Given** 凍結済みユーザーがいない、**When** 管理者が凍結一覧を開く、**Then** 「凍結中のアカウントはありません」と表示される

---

### Edge Cases

- 管理者自身を凍結しようとした場合はエラーを返す
- すでに凍結済みのユーザーを再度凍結しようとした場合は操作を拒否する
- 凍結理由が空の場合はデフォルト文言（「理由未記載」）を記録する
- 凍結中のユーザーが既にログイン済みのセッションを持っている場合、次回のアクセス時にセッションを無効化する

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理者は `/admin/users` ページで全ユーザーを一覧表示できる（ユーザー名・ID・凍結状態を表示）
- **FR-002**: 管理者はユーザー一覧から対象ユーザーを選択してアカウントを凍結できる
- **FR-003**: 管理者は凍結時に理由を入力できる（任意、省略時はデフォルト文言を記録）
- **FR-004**: 凍結されたユーザーはログインを拒否される
- **FR-005**: 凍結されたユーザーが既存セッションでアクセスした場合、次のリクエスト時にセッションを無効化しログイン画面に遷移させる
- **FR-006**: 管理者はユーザー一覧から凍結済みユーザーを選択して凍結を解除できる
- **FR-007**: 凍結・解除操作はすべて監査ログ（`admin_audit_log`）に記録される
- **FR-008**: 管理者は凍結中のアカウントを一覧上でフィルタして確認できる
- **FR-009**: 管理者自身のアカウントは凍結できない

### Key Entities

- **User**: ユーザーアカウント。凍結状態（有効・凍結）を持つ
- **AccountFreeze**: 凍結記録。対象ユーザー、凍結理由、実施日時、解除日時、実施管理者を記録

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 凍結操作から次回アクセス時までにユーザーのセッションが無効化される（即時反映）
- **SC-002**: 凍結・解除操作が100%監査ログに記録される
- **SC-003**: 管理者が凍結一覧を1画面で確認でき、各凍結の理由・日時を把握できる
- **SC-004**: 凍結済みユーザーのログイン試行に対して明示的なエラーメッセージが表示される

## Clarifications

### Session 2026-06-07

- Q: 管理者がユーザーを管理する画面をどう提供するか → A: 新規ページ `/admin/users` を作成（ユーザー一覧 + 凍結/解除ボタン）
- Q: 管理者が凍結対象ユーザーをどう特定するか → A: 全ユーザーを一覧表示し、そこから選択して凍結（名前・ID表示）

## Assumptions

- 凍結はソフトバン（論理的な状態変更）で対応し、アカウントデータは削除しない
- 既存の `admin_audit_log` テーブル（018で導入）を凍結・解除操作の記録に流用する
- 凍結中ユーザーの既存投稿は非表示にしない（投稿の可視性は別機能として扱う）
- セッション無効化は「次回アクセス時に検知」方式とし、リアルタイムのキック（WebSocket等）は対象外
- 管理者ロールの判定は既存の `session.user.role === "admin"` を使用する

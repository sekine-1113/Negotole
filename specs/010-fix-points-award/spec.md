# Feature Specification: デイリーポイント付与バグ修正

**Feature Branch**: `010-fix-points-award`

**Created**: 2026-05-26

**Status**: Draft

**Input**: User description: "再ログイン/日付更新でもポイント付与がされないバグがありそうです。調査および修正をお願いします。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 翌日の訪問で自動的にデイリーポイントが付与される（Priority: P1）

ログイン済みのユーザーが翌日（JST 日付変更後）にサイトを訪問したとき、ログアウト・再ログインせずともデイリーポイント（10pt）が自動的に付与される。現在は付与されないバグがあり、ユーザーが毎日投稿するのに必要なポイントを取得できない。

**Why this priority**: デイリーポイントはユーザーが毎日投稿するための基盤であり、付与されないとユーザーはサービスを利用できなくなる。既存セッションのまま翌日訪問するのが通常の利用パターンであるため、最優先対応が必要。

**Independent Test**: ログイン済み状態で前日のポイント残高が 0 になった翌日（JST）にページをリロードし、ポイントが 10pt 付与されることを確認する。再ログイン不要で完結する。

**Acceptance Scenarios**:

1. **Given** 前日にログインしてポイントを受け取ったユーザーが、**When** JST 日付変更後に初めてページを訪問する、**Then** 自動的に 10pt のデイリーポイントが付与され、残高に反映される
2. **Given** 前日のデイリーポイントが期限切れになっているユーザーが、**When** トップページを開く、**Then** ポイント残高に 10pt が追加される（ログアウト操作なしで）
3. **Given** 当日すでにデイリーポイントを受け取っているユーザーが、**When** ページをリロードする、**Then** ポイントが重複付与されない（1日1回のみ）

---

### User Story 2 - 再ログイン時に当日未取得の場合はポイントが付与される（Priority: P2）

ユーザーがログアウトして再ログインした際、当日のデイリーポイントをまだ受け取っていない場合（または日付が変わっていた場合）は、ログイン時にポイントが付与される。

**Why this priority**: 明示的に再ログインするユーザーにとっても付与が保証される必要がある。P1 修正の副産物として自然に解消される場合が多いが、独立して保証すべき。

**Independent Test**: 前日ポイントを受け取った後にログアウトし、翌日 JST で再ログインしてポイントが付与されることを確認する。

**Acceptance Scenarios**:

1. **Given** 前日にポイントを受け取ったユーザーが翌日に再ログインする、**When** ログインが完了する、**Then** 当日分の 10pt が自動付与される
2. **Given** 当日すでにポイントを受け取ったユーザーが同日中に再ログインする、**When** ログインが完了する、**Then** ポイントが重複付与されない

---

### Edge Cases

- ポイント付与処理が失敗（DB エラー等）した場合、ユーザーへのエラー表示なしに次回の訪問で再試行される
- JST 深夜 0 時付近（23:58〜00:02）のアクセスで日付判定が正確に行われる
- 複数タブを同時に開いた場合、ポイントが二重付与されない
- 長期間（1週間以上）ログインしなかったユーザーが久しぶりに訪問した場合、当日分の 1 回のみ付与される

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ログイン済みユーザーが各 JST カレンダー日の初回ページ訪問時に、その日のデイリーポイントが未付与であれば自動的に 10pt が付与されること
- **FR-002**: デイリーポイントの付与は 1 日 1 回のみとし、同一 JST 日内での重複付与を防止すること
- **FR-003**: ポイント付与のトリガーは再ログイン操作を必要としないこと（既存セッションのまま翌日訪問しても付与される）
- **FR-004**: ポイント付与処理はユーザーの体感レスポンス速度に悪影響を与えないこと（非同期または最小遅延での処理）
- **FR-005**: ポイント付与失敗時（DB エラー等）はサイレントに失敗し、ユーザーの操作を阻害しないこと
- **FR-006**: 投稿によるポイント消費（-1pt）は当日 JST 23:59:59 に失効する一時的な記録として扱い、翌日以降の残高に影響を与えないこと
- **FR-007**: 恒久ポイント（キャンペーン等の期限なしポイント）は投稿によるポイント消費で減少しないこと（デイリー残高のみが消費対象）

### Key Entities

- **デイリーポイント**: ユーザー 1 人につき JST カレンダー日ごとに 1 回付与される 10pt の一時ポイント。当日 JST 23:59:59 に失効する
- **消費ポイント**: 投稿 1 回につき記録される -1pt のポイント消費。当日 JST 23:59:59 に失効するため、デイリーポイントと同期して翌日以降に持ち越されない
- **恒久ポイント**: キャンペーン等で付与される期限なしポイント（`expiresAt: null`）。投稿によるポイント消費の影響を受けない
- **ポイント付与判定**: 当日の付与済みレコードの有無を JST 日付基準で確認する処理

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ログイン済みユーザーが翌日にページを訪問した際、再ログインなしに 10pt が付与されること（手動テストで確認可能）
- **SC-002**: 同一 JST 日内で複数回ページをリロードまたはログインしても、ポイントが 1 回のみ付与されること（DB レコード数で確認）
- **SC-003**: ポイント付与処理により、ページの初期表示が 300ms 以上遅延しないこと
- **SC-004**: 既存の 23 テストがすべてパスし、デグレが発生しないこと

## Assumptions

- デイリーポイント付与の基準時刻は JST（日本標準時、UTC+9）の 0:00 である
- ポイント 1 回あたりの付与量（10pt）は変更しない
- ポイント失効タイミング（当日 JST 23:59:59）は変更しない
- 既存の `hasDailyPointToday()` および `grantDailyPoints()` 関数のロジック自体は正しい（修正対象はトリガーのタイミング）
- セッション管理の実装詳細（JWT 戦略等）は変更しない
- 投稿による消費ポイントはデイリーポイントと同じ失効時刻（当日 JST 23:59:59）を使用し、翌日にリセットされる
- ポイント残高の内訳：`daily`（当日有効の一時ポイント合計）、`permanent`（恒久ポイント合計）、`total`（daily + permanent）

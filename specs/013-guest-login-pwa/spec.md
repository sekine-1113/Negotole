# Feature Specification: ゲストログイン限定化 & PWA対応

**Feature Branch**: `013-guest-login-pwa`

**Created**: 2026-05-28

**Status**: Draft

**Input**: User description: "プロトタイプ版として、Googleログインは一度非表示にし、ゲストとしてログインのみ選択可能にしてください。また、PWA対応をお願いします。"

## Clarifications

### Session 2026-05-28

- Q: ゲストセッションの有効期間とデータ永続化はどう扱うか → A: ブラウザを閉じるとセッション終了。投稿などのデータはゲスト ID に紐づくがセッション消失後は孤立（投稿は表示されるが所有者なし）。ゲストは書き込み（投稿・ポイント獲得）も可能だが永続セッションはなし。
- Q: サービスワーカーのキャッシュ戦略の範囲はどこまでか → A: 静的アセット（JS・CSS・フォント・PWA アイコン）のみキャッシュ。タイムライン等の API データはキャッシュしない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ゲストとしてサービスを利用する (Priority: P1)

初めて訪れたユーザーがログイン画面を開くと、「ゲストとしてログイン」ボタンのみが表示される。ユーザーはそのボタンをタップするだけでサービスを利用開始できる。Googleログインのボタンは表示されない。

**Why this priority**: プロトタイプ段階でのユーザー体験の主軸。ゲストログインの動作確認がプロトタイプ検証の前提となるため、最優先。

**Independent Test**: ログイン画面にアクセスして「ゲストとしてログイン」ボタンのみが表示され、タップ後にタイムラインへ遷移することを確認することで独立してテスト可能。

**Acceptance Scenarios**:

1. **Given** 未ログイン状態でアプリを開いた、**When** ログイン画面を表示する、**Then** 「ゲストとしてログイン」ボタンのみが表示され、Googleログインのボタンは表示されない
2. **Given** ログイン画面が表示されている、**When** 「ゲストとしてログイン」をタップする、**Then** ゲストユーザーとしてサービスにアクセスでき、タイムラインが表示される
3. **Given** ゲストとしてログイン済み、**When** 投稿・閲覧などの操作を行う、**Then** 通常ユーザーと同等の基本機能が利用できる

---

### User Story 2 - スマートフォンにアプリとしてインストールする (Priority: P2)

スマートフォンでサービスにアクセスしたユーザーが、ブラウザの「ホームに追加」機能を使ってアプリとして端末にインストールできる。インストール後はネイティブアプリのようにアイコンから起動し、ブラウザのUIが表示されないフルスクリーン表示で利用できる。

**Why this priority**: PWA対応によりユーザーが繰り返しアクセスしやすくなる。ゲストログインと並行して進められる独立した機能のため P2。

**Independent Test**: スマートフォンのブラウザからアクセスし、「ホームに追加」が表示されること、インストール後にアプリアイコンから起動してスタンドアローンモードで表示されることを確認。

**Acceptance Scenarios**:

1. **Given** スマートフォンのブラウザでサービスを開いた、**When** インストールプロンプトが表示される、**Then** 「ホームに追加」または「インストール」の案内が出てインストールできる
2. **Given** アプリをホーム画面にインストールした、**When** アイコンからアプリを起動する、**Then** ブラウザのアドレスバーや UI なしのフルスクリーン表示でアプリが起動する
3. **Given** PWA としてインストールされている、**When** アプリアイコンとスプラッシュスクリーンが表示される、**Then** サービスのブランドカラーとアイコンが一貫して表示される

---

### Edge Cases

- Googleログインボタンが非表示になっても、既存の Google ログインセッション（既にログイン済みのユーザー）は引き続き利用できる（既存セッションは維持する）
- ゲストユーザーとしてログインした場合、投稿やポイント付与は可能だが、ブラウザを閉じるとセッションが終了し、ゲスト ID と紐づくデータは孤立状態になる（投稿は表示されるが再ログイン後は別のゲスト ID となる）
- PWA のオフラインサポートは基本的なキャッシュのみとし、ネットワーク断絶時の完全動作は範囲外
- iOS Safari での「ホームに追加」は対応対象とするが、プッシュ通知は範囲外
- インストールプロンプトを一度拒否したユーザーへの再表示は行わない

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ログイン画面にて、Googleログインのボタンを非表示にする
- **FR-002**: ログイン画面にて、「ゲストとしてログイン」ボタンのみを表示する
- **FR-003**: 「ゲストとしてログイン」ボタンをタップすると、ゲストユーザーとしてサービスにアクセスできる
- **FR-004**: 既存の Google ログインセッションを持つユーザーは、引き続きサービスを利用できる（セッション破棄はしない）
- **FR-005**: アプリは PWA としてインストール可能な要件（Web アプリマニフェスト、サービスワーカー）を満たす
- **FR-006**: Web アプリマニフェストにアプリ名・アイコン・テーマカラー・表示モード（standalone）を設定する
- **FR-007**: サービスワーカーによって静的アセット（JS・CSS・フォント・PWA アイコン）をキャッシュし、繰り返しアクセス時の初期表示を高速化する。タイムライン等の API データはキャッシュしない
- **FR-008**: アプリアイコンは複数サイズ（最低 192×192、512×512）で用意し、ホーム画面への追加に対応する

### Key Entities

- **ゲストセッション**: ゲストユーザーとして識別される一時的なセッション情報。ブラウザを閉じるとセッションが終了し、次回アクセス時は新しいゲスト ID が発行される。セッション中は投稿・ポイント獲得が可能だが、セッション終了後はそれらデータと再接続できない
- **PWA マニフェスト**: アプリ名、アイコン、起動 URL などアプリとしての振る舞いを定義する設定情報
- **サービスワーカー**: キャッシュ戦略を管理し、繰り返しアクセス時の高速表示を実現する仕組み

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ログイン画面を開いたとき、Googleログインボタンが表示されず、ゲストログインボタンのみが表示される（100%の確率で）
- **SC-002**: ゲストとしてログインボタンをタップしてから、タイムライン表示までが3秒以内に完了する
- **SC-003**: スマートフォンのブラウザでアクセスした際、PWA インストールプロンプトが表示される
- **SC-004**: インストールした PWA をアイコンから起動した際、スタンドアローンモード（ブラウザ UI 非表示）で表示される
- **SC-005**: 2回目以降のアクセスで、静的アセットのキャッシュにより初回より表示開始が速くなる（JS/CSS の再ダウンロードが不要）

## Assumptions

- プロトタイプ段階であるため、Googleログインの無効化は表示上の非表示（UI から削除）で対応し、バックエンドの OAuth 設定は変更しない
- 既存のゲストログイン機能（NextAuth ゲストプロバイダー等）はすでに実装済みであることを前提とする
- PWA のオフライン機能（ネットワーク断絶時の完全動作）は本フィーチャーの範囲外とし、基本的なキャッシュのみ実装する
- アプリアイコン画像素材はこの機能で新規作成または既存ロゴから生成する
- iOS (Safari) と Android (Chrome) の両プラットフォームでの PWA インストールを対象とする
- プッシュ通知は本フィーチャーの範囲外

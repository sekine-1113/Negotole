# Feature Specification: レスポンシブデザイン対応（モバイルファースト）

**Feature Branch**: `009-mobile-responsive`

**Created**: 2026-05-26

**Status**: Draft

**Input**: User description: "レスポンシブ対応してほしい。モバイルファーストでお願いします。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - スマートフォンでタイムラインを閲覧・投稿できる（Priority: P1）

スマートフォンを持つユーザーが Negotole にアクセスした際、横スクロールなしにタイムライン・ナビゲーション・投稿フォームが快適に使える。ヘッダーのボタンやリンクはタップしやすく、テキストは読みやすいサイズで表示される。

**Why this priority**: ユーザーの多くがスマートフォンからアクセスすることが想定される。現在のヘッダーが小画面で押し込まれる可能性があり、最優先で対応が必要。

**Independent Test**: iPhone SE（375px 幅）相当の画面サイズで以下を確認する: (1) タイムラインが横スクロールなしに表示される、(2) ヘッダーのすべてのボタンがタップ可能なサイズで表示される、(3) 投稿フォームの全要素が画面内に収まる。

**Acceptance Scenarios**:

1. **Given** 画面幅 375px のスマートフォンでトップページを開く、**When** ページが表示される、**Then** 横スクロールバーが発生せずタイムラインが縦に並んで表示される
2. **Given** ログイン済みユーザーが小画面でヘッダーを見る、**When** ヘッダーを確認する、**Then** ロゴ・ポイント表示・「投稿する」ボタン・「ログアウト」ボタンがすべて操作可能な状態で表示される（重なり・見切れなし）
3. **Given** スマートフォンで投稿フォームを開く、**When** テキストエリアをタップして入力する、**Then** キーボードが表示されてもフォームのレイアウトが崩れず、送信ボタンが操作できる
4. **Given** 未ログインユーザーが小画面でトップページを開く、**When** ヘッダーを確認する、**Then** 「Google でログイン」ボタンが適切なサイズで表示される

---

### User Story 2 - 管理画面がタブレット・スマートフォンで使える（Priority: P2）

管理者がタブレットやスマートフォンでキャンペーン一覧・作成・編集にアクセスした際、テーブルのデータが見やすく表示され、フォームが操作しやすい。

**Why this priority**: 管理者が外出先でキャンペーンを確認・編集できることで運用効率が向上する。P1 のメインコンテンツ対応後に着手。

**Independent Test**: タブレット（768px 幅）およびスマートフォン（375px 幅）でキャンペーン一覧ページを開き、(1) テーブルのデータが横スクロールで確認できる、または (2) カード形式に変わって全情報が読める、のいずれかを確認する。

**Acceptance Scenarios**:

1. **Given** 小画面でキャンペーン一覧（`/admin/campaigns`）を開く、**When** ページが表示される、**Then** テーブルが横スクロール可能な形で表示されるか、またはカードレイアウトに変換されてデータが読める
2. **Given** スマートフォンでキャンペーン新規作成フォームを開く、**When** 各フィールドをタップして入力する、**Then** 入力フィールドが適切な幅で表示され、入力時にレイアウトが崩れない
3. **Given** 管理者がスマートフォンで編集リンクをタップする、**When** リンクが表示される、**Then** 「編集」リンクのタップ領域が十分な大きさで表示される

---

### Edge Cases

- 画面幅 320px（最小サイズのスマートフォン）でコンテンツが見切れないこと
- 長い投稿テキストが折り返して表示されること（横はみ出しなし）
- ログイン済み状態でヘッダー要素が多い場合でも小画面で崩れないこと
- 横向き（landscape）表示でもレイアウトが適切に表示されること

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 画面幅 320px 以上のすべての画面でコンテンツが横スクロールなしに表示されること（管理画面テーブルを除く）
- **FR-002**: すべてのタップ対象要素（ボタン・リンク）の縦横それぞれが 44px 以上の操作領域を持つこと。視覚的なコンパクトスタイルを維持しながら `min-h-[44px]` 相当の最小タップ領域を各ボタンに確保すること
- **FR-003**: ヘッダーのナビゲーション要素が画面幅 375px 以上で見切れ・重なりなしに表示されること
- **FR-004**: 管理画面のキャンペーン一覧テーブルが横スクロール対応またはモバイル向けレイアウトで表示されること
- **FR-005**: テキスト入力フィールドが 16px 以上のフォントサイズで表示され、iOS でのズームを防止すること
- **FR-006**: 投稿フォームがスマートフォンのソフトウェアキーボード表示時に使用可能であること
- **FR-007**: モバイルファースト設計で実装し、小画面を基準としてより大きな画面へ拡張するスタイルとすること

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 画面幅 320px・375px・768px・1024px のすべての代表的なブレークポイントで横スクロールが発生しない（管理テーブルを除く）
- **SC-002**: すべてのボタン・リンクのタップ領域が 44×44px 以上（WCAG 2.1 成功基準 2.5.5 相当）
- **SC-003**: Lighthouse モバイルスコアの「パフォーマンス」に影響する変更がなく、既存スコアを維持する
- **SC-004**: 既存の 23 テストがすべてパスする（デグレなし）

## Clarifications

### Session 2026-05-26

- Q: ヘッダーのコンパクトスタイルで 44×44px タップ領域（FR-002）を満たす方法 → A: 各ボタンに `min-h-[44px]` を追加してタップ領域を確保（視覚的なコンパクトさは維持）

## Assumptions

- 対象ブレークポイント: 320px（小スマートフォン）、375px（標準スマートフォン）、768px（タブレット）、1024px（デスクトップ）
- スタイリングは既存の CSS ユーティリティクラスの仕組みを使用する（実装詳細は planning 段階で決定）
- 管理画面テーブル（`/admin/campaigns`）は横スクロールでの対応を最低限として、カード化はオプション
- デスクトップでの既存の見た目を維持しつつ小画面向けに最適化する
- 対象コンポーネント: `Header`・`PostCard`・`PostForm`・`Timeline`・管理画面ページ群（`/admin/campaigns`、新規作成、編集）

# Feature Specification: キャンペーンポイント適用ロジック

**Feature Branch**: `016-campaign-point-application`

**Created**: 2026-06-07

**Status**: Draft

**Input**: `docs/claude_todo.md` — キャンペーンポイントの適用ロジック（各キャンペーン1ユーザー1回・期間限定or恒久ポイント）

## User Scenarios & Testing *(mandatory)*

### User Story 1 — キャンペーン期間中にログインしたユーザーがボーナスポイントを受け取る (Priority: P1)

ユーザーとして、アクティブなキャンペーン期間中にログインしたとき、そのキャンペーンのボーナスポイントを自動的に受け取りたい。ただし同じキャンペーンで2回以上ポイントをもらうことはない。

**Why this priority**: 現状、新規ユーザーのみキャンペーンポイントが付与されており、既存ユーザーはキャンペーン期間中にログインしても恩恵を受けられない。キャンペーンの主目的（参加促進・継続利用）が達成できていない。

**Independent Test**: アクティブなキャンペーン期間中に既存ユーザーがログインし、残高にキャンペーンのボーナスポイントが加算されることを確認する。同じユーザーが再度ログインしても追加付与されないことを確認する。

**Acceptance Scenarios**:

1. **Given** アクティブなキャンペーンが存在する、**When** 既存ユーザーがログインする、**Then** そのキャンペーンのボーナスポイントが付与される
2. **Given** 同じユーザーが同じキャンペーン期間中に再度ログインする、**When** ログイン処理が完了する、**Then** ボーナスポイントは追加付与されない（1回のみ）
3. **Given** キャンペーンが存在しない（またはキャンペーン期間外）、**When** ユーザーがログインする、**Then** キャンペーンボーナスは付与されない
4. **Given** キャンペーンAのボーナスを受け取ったユーザー、**When** 新しいキャンペーンBが始まりログインする、**Then** キャンペーンBのボーナスポイントが付与される（キャンペーンごとに独立して管理）

---

### User Story 2 — キャンペーンのポイントに期限を設定できる (Priority: P2)

管理者として、キャンペーンを作成するとき、付与するボーナスポイントを「期間限定（キャンペーン終了日まで有効）」または「恒久（無期限）」のどちらにするか選択したい。

**Why this priority**: 現状すべてのキャンペーンポイントが恒久扱いになっている。マーケティング戦略上、特定のキャンペーンでは期間限定ポイントを使って緊急性を演出したい場合がある。

**Independent Test**: 管理者がキャンペーン作成フォームでポイント種別（恒久/期間限定）を選択できる。期間限定を選択したキャンペーンのポイントが付与されたとき、有効期限がキャンペーン終了日に設定されることを確認する。

**Acceptance Scenarios**:

1. **Given** 管理者がキャンペーン作成フォームを開く、**When** フォームを確認する、**Then** ポイント種別（恒久/期間限定）を選択するオプションが表示される
2. **Given** 「期間限定」を選択してキャンペーンを作成した、**When** そのキャンペーン期間中にユーザーがログインする、**Then** 付与されるポイントの有効期限がキャンペーン終了日に設定される
3. **Given** 「恒久」を選択してキャンペーンを作成した、**When** そのキャンペーン期間中にユーザーがログインする、**Then** 付与されるポイントに有効期限が設定されない（無期限）

---

### Edge Cases

- キャンペーンポイント付与中にエラーが発生した場合は、ログイン自体を妨げず静かに失敗する（現在の仕様を踏襲）
- ユーザーが複数のデバイスから同時にログインした場合でも、1キャンペーンにつき1回のみ付与される（重複付与を防ぐ）
- キャンペーン期間中にキャンペーンが削除（論理削除）された場合、以降の付与は行わない

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはキャンペーンとユーザーの適用履歴を管理し、同一キャンペーン・同一ユーザーの重複付与を防ぐ
- **FR-002**: アクティブなキャンペーンが存在する場合、ログイン時に未適用のユーザー全員に自動でボーナスポイントを付与する（新規ユーザーに限定しない）
- **FR-003**: キャンペーンには「恒久（無期限）」または「期間限定（キャンペーン終了日まで）」のポイント種別を設定できる
- **FR-004**: 管理者はキャンペーン作成・編集フォームでポイント種別を選択できる
- **FR-005**: 期間限定ポイントとして付与された場合、ポイントの有効期限はキャンペーンの終了日時と一致する
- **FR-006**: キャンペーンポイントの付与はログイン時に自動的に行われ、ユーザーの明示的なアクションを必要としない

### Key Entities

- **Campaign（キャンペーン）**: 既存。`bonusPoints`（付与ポイント数）に加え、ポイント種別（恒久/期間限定）の属性を追加する
- **CampaignApplication（キャンペーン適用履歴）**: 新規。どのユーザーがどのキャンペーンのポイントを受け取ったかを記録する。`campaignId`・`userId`・適用日時を持つ。同一の `(campaignId, userId)` の組み合わせは一意である

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: キャンペーン期間中に既存ユーザーがログインしたとき、ポイント残高にボーナスポイントが加算される（1回のみ）
- **SC-002**: 同一ユーザーが同一キャンペーン期間中に複数回ログインしても、ポイント付与は1回のみ
- **SC-003**: 管理者がキャンペーン作成フォームでポイント種別（恒久/期間限定）を選択できる
- **SC-004**: 期間限定ポイントの有効期限がキャンペーンの終了日と一致している

## Assumptions

- キャンペーン適用履歴テーブルを新規追加し、データベースマイグレーションを実施する
- ポイント種別のデフォルトは「恒久」とする（既存キャンペーンとの後方互換性を維持）
- キャンペーンポイント付与のタイミングはログイン時のみとする（定期バッチは対象外）
- 既存ユーザーが過去のキャンペーン（本機能追加前）のポイントを遡及的に受け取ることはない
- キャンペーン適用履歴テーブルの作成後、新規作成されるキャンペーンから管理が始まる
- ポイント種別は「恒久」か「期間限定（キャンペーン終了日まで）」の2択とする（カスタム期限は対象外）

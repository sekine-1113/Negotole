# Feature Specification: Negotole - 時間限定投稿 SNS

**Feature Branch**: `001-negotole-sns-spec`

**Created**: 2026-05-24

**Status**: Draft

**Input**: docs を参照し、Negotole アプリ全体の実装仕様をブラッシュアップ

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 匿名タイムライン閲覧 (Priority: P1)

訪問者はログインせずにトップページにアクセスし、現在有効な投稿の一覧を新着順に閲覧できる。投稿には本文と残り時間のみが表示され、投稿者の情報は一切見えない。

**Why this priority**: ログインバリアなしに一期一会の体験を提供することがサービスの核心。これだけで「眺めるだけの訪問者」に価値を届けられる。

**Independent Test**: ログインなしでトップページを開き、投稿一覧が表示され残り時間がカウントダウンされることを確認できる。

**Acceptance Scenarios**:

1. **Given** 未ログインの訪問者がトップページを開いた、**When** ページが読み込まれる、**Then** 有効期限内の投稿が新着順に最大 20 件表示される
2. **Given** 投稿一覧が表示されている、**When** 各投稿カードを確認する、**Then** 本文と残り時間のみが表示され、投稿者名・アカウント情報は表示されない
3. **Given** 投稿一覧の末尾まで到達した、**When** 「もっと見る」を押す、**Then** 次の 20 件が追加表示される
4. **Given** ある投稿の `hidden_at` が現在時刻を過ぎた、**When** ページをリロードする、**Then** その投稿は一覧に表示されない

---

### User Story 2 - Google ログインとアカウント作成 (Priority: P2)

投稿したいユーザーは Google アカウントでログインする。初回ログイン時はアカウントが自動作成され、その日のポイント（10pt）が付与される。

**Why this priority**: 投稿機能の前提条件。ログインが確立しないと P3 以降のシナリオに進めない。

**Independent Test**: Google でログインするとユーザー情報が保存され、ヘッダーにポイント残量が表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 未ログインユーザーがログインボタンを押した、**When** Google 認証を完了する、**Then** トップページに戻りヘッダーにポイント残量が表示される
2. **Given** 初回ログインのユーザーが認証を完了した、**When** コールバック処理が走る、**Then** ユーザーレコードが作成され当日分 10pt が付与される
3. **Given** 当日すでにログイン済みのユーザーが再ログインした、**When** コールバック処理が走る、**Then** デイリーポイントの重複付与は発生しない
4. **Given** 日付が変わった翌日にログインした、**When** コールバック処理が走る、**Then** 前日のデイリーポイントは失効し、新たに 10pt が付与される

---

### User Story 3 - 時間限定投稿の作成 (Priority: P3)

ログイン済みのユーザーは本文（最大 255 文字）と表示制限時間（1/3/6/12/24 時間から選択）を入力し、1pt を消費して投稿できる。投稿はタイムラインに即時反映され、選択した時間が経過すると自動的に消える。

**Why this priority**: サービスの主機能。P1・P2 が動いた後に初めて価値が完結する。

**Independent Test**: ログイン後に投稿フォームから投稿し、タイムラインに表示されること、および選択した時間後に消えることを確認できる。

**Acceptance Scenarios**:

1. **Given** ログイン済みでポイント残量 ≥ 1pt のユーザーが投稿フォームを開いた、**When** 本文と制限時間を選択して「投稿する」を押す、**Then** 投稿が保存されタイムラインに即時表示される
2. **Given** 投稿が完了した、**When** ポイント残量を確認する、**Then** 投稿前より 1pt 減っている
3. **Given** ポイント残量が 0pt のユーザーが投稿フォームを開いた、**When** 投稿フォームを確認する、**Then** 「投稿する」ボタンが非活性になりポイント不足メッセージが表示される
4. **Given** 投稿の `hidden_at` に設定された時刻が経過した、**When** タイムラインを確認する、**Then** その投稿は表示されない
5. **Given** ユーザーが 255 文字を超える本文を入力した、**When** 投稿操作を試みる、**Then** 投稿は拒否され文字数超過のエラーが表示される

---

### Edge Cases

- 投稿中にセッションが切れた場合、未保存の入力内容を失わずに再ログインへ誘導する
- 複数タブで同じユーザーが投稿した場合、ポイントは正確に二重消費される（重複防止は行わない）
- デイリーポイントが 0pt で恒久ポイントもない場合、投稿ボタンは非活性になる
- 投稿本文が空文字または空白のみの場合、投稿は拒否される
- 制限時間を選択せずに「投稿する」を押した場合、バリデーションエラーを表示する

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはログインなしでタイムライン（有効期限内の投稿一覧）を表示しなければならない
- **FR-002**: システムはタイムラインの各投稿カードに投稿者の識別情報（名前・アカウント等）を表示してはならない
- **FR-003**: システムは Google OAuth を使ったログインを提供しなければならない
- **FR-004**: システムは初回ログイン時にユーザーレコードを自動作成しなければならない
- **FR-005**: システムはログインのたびに当日分のデイリーポイント（10pt）未付与であれば付与しなければならない
- **FR-006**: システムはデイリーポイントを当日 23:59:59 に失効させなければならない
- **FR-007**: ユーザーは本文（1〜255 文字）と表示制限時間（1/3/6/12/24 時間）を選択して投稿できなければならない
- **FR-008**: システムは投稿ごとに 1pt を消費しなければならない
- **FR-009**: システムはポイント残高が 0pt の場合に投稿を拒否しなければならない
- **FR-010**: システムは投稿の `hidden_at` を超えた投稿をタイムラインに表示してはならない
- **FR-011**: システムはいいね・コメント・フォロー・DM 機能を提供してはならない
- **FR-012**: システムはタイムラインをカーソルベースのページネーション（1ページ 20 件）で提供しなければならない
- **FR-013**: システムは各投稿カードに `hidden_at` までの残り時間をリアルタイムで表示しなければならない
- **FR-014**: ログイン済みユーザーはヘッダーでポイント残量（デイリー・恒久の合計）を確認できなければならない
- **FR-015**: システムはすべての削除を論理削除（`deleted_at`）で行い、物理削除は行わない

### Key Entities *(include if feature involves data)*

- **ユーザー (User)**: Google アカウントで識別される投稿者。表示名と生年を持つ。タイムライン上では匿名
- **投稿 (Post)**: 本文（最大 255 文字）と有効期限（hidden_at）を持つ時間限定コンテンツ。作成者の情報は公開しない
- **ポイント履歴 (UserPoint)**: ユーザーごとの付与・消費の記録。正の値が付与、負の値が消費。デイリーポイントは有効期限付き、恒久ポイントは期限なし

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 未ログインの訪問者がトップページを開いてから投稿一覧が表示されるまで 2 秒以内
- **SC-002**: ログインから最初の投稿完了まで 3 分以内に達成できる
- **SC-003**: ポイント不足・文字数超過・時間未選択などの入力エラーを 100% 投稿前に検知し、ユーザーに明示できる
- **SC-004**: 有効期限が切れた投稿がタイムラインに表示され続ける時間はページリロード後 0 秒（サーバーサイドで除外済み）
- **SC-005**: 同一ユーザーの同一日のデイリーポイント重複付与が 0 件
- **SC-006**: 投稿カードに投稿者情報が表示されるケースが 0 件

---

## Assumptions

- タイムラインの閲覧はログイン不要だが、投稿にはログインが必須
- ユーザープロフィールページは提供しない（自分の過去投稿の確認機能も v1 では持たない）
- 恒久ポイントの付与フロー（特殊操作）は v1 には含めない。付与ロジックのデータモデルのみ対応する
- デイリーポイントと恒久ポイントが両方ある場合、デイリーポイントを優先消費する（v1 仮定）
- タイムラインは全ユーザーの投稿を混在表示する。パーソナライズや絞り込みは行わない
- モバイル対応は v1 のスコープに含めるが、専用アプリ（iOS/Android）は対象外
- 投稿の手動削除（自分の投稿を消す）機能は v1 のスコープ外

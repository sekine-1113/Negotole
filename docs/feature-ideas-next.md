## A. 既存リストの未実装分

### A-2. 読後消滅

- **概要**: スクロールで通過した投稿は次回起動時に表示されない（localStorage で既読 ID を管理）
- **実装規模**: 小
- **未実装の理由**: 実装は簡単だが、既読 ID の肥大化（localStorage の上限）とゲスト引継ぎ時の挙動を先に詰める必要がある
- **補足**: ID のセットを localStorage に保存。古い ID（7日以上前）は自動パージして上限対策。ゲスト引継ぎ後は既読リストをリセットして「新しい出会いとして再開」とする
- **哲学**: 「もう一度あの投稿を確認しよう」を不可能にする。出会いは一度きり

### A-7. 投稿後の沈黙

- **概要**: 投稿完了後に「投稿しました」トーストやプレビューを表示しない。フォームがリセットされるだけ
- **実装規模**: 極小
- **現状**: `PostForm` では投稿後に `/` へ `router.push` しているため、実質的にタイムラインが開く。これをフォームリセットのみに変更する
- **注意**: ポイント残高の表示は更新が必要（ヘッダー `revalidate` を呼ぶか SWR で自動更新）
- **哲学**: 「ちゃんと届いたか確認したい」という衝動を生まない

### A-10. タイムカプセル投稿

- **概要**: 投稿したが、指定時刻（例：8時間後）まで公開を遅らせる
- **実装規模**: 中
- **DB 変更**: `post` テーブルに `published_at timestamp` カラム追加。タイムラインクエリに `published_at IS NULL OR published_at <= NOW()` 条件追加
- **UI**: PostForm の期限選択に「N時間後に公開」オプションを追加
- **マイページ**: 「予約投稿」タブで未公開の投稿一覧を表示（本人のみ）
- **哲学**: 書いた直後に反応を確認する行動が不可能になる。書く行為と公開の間に時間的断絶を入れる

### A-11. 1日1投稿モード

- **概要**: 1日1件に制限するユーザー自身が有効化するオプション
- **実装規模**: 小
- **実装**: マイページ設定に「1日1投稿モード」トグル。有効時は `user_point` の当日投稿消費レコード数で判定（API 側でガード + フロント表示）。DBに設定カラムは不要（localStorage で管理し、サーバー側は「当日1件以上投稿済みか」を常にチェック）
- **注意**: localStorage なのでデバイスまたぎで無効化できてしまう。設計思想上はユーザーの自己責任として許容
- **哲学**: 量で承認獲得を狙う行動を自ら制限する

### A-17. 匿名グループ表示

- **概要**: 深夜帯の投稿を「今夜 X 人が孤独を書いた」「今夜 Y 人が感謝を書いた」のように感情カテゴリ別集計で表示
- **実装規模**: 中
- **実装**: 感情キーワード辞書（`孤独・寂しい・眠れない` → "孤独"、`ありがとう・感謝・嬉しい` → "感謝" など）をサーバー側に持つ。定期バッチ or リクエスト時に集計して表示コンポーネントへ
- **補足**: キーワードマッチのため精度は低いが、集計の不正確さ自体がコンテンツの軽さとして許容される
- **哲学**: 個人の投稿ではなく「今夜の集合的な感情の地図」を見る体験

### A-19. 天気連動ポイント

- **概要**: デイリーポイント付与量が天気によって変わる（晴れ=10pt、雨=12pt、雪=15pt）
- **実装規模**: 中
- **実装**: [Open-Meteo](https://open-meteo.com/)（無料・APIキー不要）を使い、ログイン時にサーバー側から現在地または日本全域の天気を取得。`grantDailyPoints` の引数を可変化
- **注意**: IPから位置情報を推定するか、日本代表地点（東京）の天気で一律にするかは設計次第
- **哲学**: ポイントを「稼ぐ」ものではなく、世界の状態が偶然決めるものとして位置づける

### A-20. 「今日書かなくていい」の明示

- **概要**: マイページに「今日ポイントを使い切らなくても、明日また付与されます」という常時表示テキスト
- **実装規模**: 極小（静的テキストを UI に追加するだけ）
- **哲学**: デイリーポイントが「今日中に消費しなければ損」という焦りを打ち消す

## B. 新規アイデア（031 以降）

### タイムライン体験

#### B-1. 「あと 1 分で消える」ウォッチ

- **概要**: 残り 60 秒以下の投稿のみを集めた小さなエリア（またはピン留め）を Timeline 上部に表示する
- **実装規模**: 小
- **実装**: `posts` state から `remainingMs < 60_000` のものをフィルターして別リストとして上部に固定表示。既存の `isNearExpiry` ロジックの延長
- **哲学**: 消えていく言葉を「見届ける」体験。数値ではなく「今ここにある最後の瞬間」として提示する

#### B-2. 読む速度に合わせた自動スクロール（オプション）

- **概要**: ユーザーが操作しなくても、ゆっくりとタイムラインが下に流れていくモード（映画のエンドロールのように）
- **実装規模**: 小
- **実装**: 設定ボタンで `requestAnimationFrame` ループを on/off。スクロール速度はデフォルト 30px/s 程度、`prefers-reduced-motion` を尊重して無効化
- **哲学**: 「何を読もうか」を考えずに言葉が流れてくる状態。能動的な選択を減らす

#### B-3. タイムラインの「間」が時刻によって変わる

- **概要**: 投稿カード間の余白が時間帯によって変わる（深夜は広い余白 → ゆったり読む、昼は狭い → 密度が高い）
- **実装規模**: 極小
- **実装**: `getStableMargin` に JST 時間帯係数を乗算するだけ（例：22:00-5:00 は 2 倍）
- **哲学**: タイムラインの体験が現実の時間と連動している感覚

#### B-4. 消えた件数の「気配」

- **概要**: 「今日、N 件の言葉がここを旅立った」を Timeline 下部にひっそり表示する（API で `deletedToday` カウントを返す）
- **実装規模**: 小
- **実装**: `fetchPosts` のレスポンスに `expiredToday: number`（当日 `hidden_at <= NOW()` の件数）を追加。Timeline の末尾に薄いテキストとして表示
- **哲学**: 消えたものへの追悼。「ここに言葉があった」という事実を残す

### 投稿体験

#### B-5. 投稿前の「間」（カウントダウン確認）

- **概要**: 投稿ボタンを押してから 3 秒後に実際に送信する。その間はキャンセル可能
- **実装規模**: 小
- **実装**: PostForm で `pending` state を導入。ボタン押下 → `setTimeout(3000)` → 送信。3 秒間は「キャンセル」ボタンを表示
- **哲学**: 衝動的な投稿を減らす。「本当にこれでいいか」という自然な問いかけ

#### B-6. ポイントを「使い切る」前の一言

- **概要**: ポイント残量が 1pt（最後の 1 投稿）になったとき、投稿フォームに「今日最後の一言です」と表示する
- **実装規模**: 極小（ポイント残高 === 1 のときテキストを変えるだけ）
- **哲学**: 最後の言葉であることを意識させる。後悔のない一言を選ばせる

#### B-7. 「書かずに捨てる」メモ帳

- **概要**: 投稿せずに文章を書いて消せる欄。翌日にはリセットされる。タイムラインには出ない
- **実装規模**: 極小（フロントのみ。localStorage に今日の日付をキーとして保存、翌日読み込んだら内容を破棄）
- **哲学**: 「投稿するほどではないが書きたい」という衝動を受け止める。出力の場として SNS を使わなくていい

### 表示・演出

#### B-8. 投稿の文字数で文字サイズが変わる

- **概要**: 投稿本文が短いほど大きいフォントサイズ、長いほど小さいフォントサイズで表示する
- **実装規模**: 極小
- **実装**: PostCard で `content.length` に応じて `text-lg/text-base/text-sm/text-xs` をマッピング
- **哲学**: 一言の重さが視覚的に際立つ。長文が「より多く読まれる」という有利さを消す

#### B-9. モノクロ + セピア選択

- **概要**: 現在のモノクロモード（grayscale）に加えてセピアトーンを追加
- **実装規模**: 極小（`filter: sepia(0.7)` を追加、localStorage の値で 3 択）
- **哲学**: 色の刺激をさらに選択的に制御できる

#### B-10. フォントの「疲れ具合」

- **概要**: JST 深夜帯（22:00〜5:00）はフォントウェイトを細く（font-light）する。昼間との視覚的なコントラスト
- **実装規模**: 極小（`globals.css` でメディアクエリの代わりに JS で時刻判定 → `body` クラス切り替え）
- **哲学**: 深夜に読む体験が昼間と違う感触になる。意図的な疲弊感

### ユーザー設定・マイページ

#### B-11. 投稿時間帯ヒートマップ（自己分析）

- **概要**: マイページに自分がいつ投稿してきたかの時間帯別グラフを表示（0〜23時の棒グラフ）
- **実装規模**: 小
- **実装**: `/api/users/me/posts/stats` エンドポイントで `GROUP BY EXTRACT(HOUR FROM created_at AT TIME ZONE 'Asia/Tokyo')` を集計して返す
- **注意**: 件数ではなく「時間帯」だけを見せる（投稿数を競わせない）。縦軸ラベルは数値ではなく「・」程度に抑える
- **哲学**: 自分がいつ言葉を書いてきたかを知る。パフォーマンスの可視化ではなく自己観察

#### B-12. 今日の一言（書く前に読む）

- **概要**: 投稿フォームを開いたとき、過去の自分の投稿（ランダム 1 件）をぼんやり表示する。消えかけの過去の自分の声
- **実装規模**: 小
- **実装**: マイポスト一覧から期限切れ（`deleted_at IS NULL AND hidden_at <= NOW()`）のものをランダム 1 件取得して PostForm 上部に薄く表示
- **哲学**: 「前に自分が何を書いたか」を見る。承認欲求ではなく自己との対話

### 管理・インフラ

#### B-13. 投稿言語検出フィルター（管理者向け）

- **概要**: 投稿本文が日本語でない場合にフラグを立てる（スパム・不正利用検出補助）
- **実装規模**: 小
- **実装**: `franc` などの軽量言語検出ライブラリを使用。投稿 API で検出し `language` カラム（`post` テーブルへの追加）に記録。管理画面でフィルタリング可能に
- **哲学**: 管理効率の向上。日本語圏向けサービスとしての整合性

#### B-14. 投稿データの週次アーカイブ（管理者）

- **概要**: 期限切れの投稿を週次で JSON にエクスポートして S3 / R2 に保存する
- **実装規模**: 中
- **実装**: Vercel Cron Job（週次）で `hidden_at <= NOW() - INTERVAL '7 days'` の投稿を取得 → JSON 化 → Cloudflare R2 or Vercel Blob に保存。管理ダッシュボードからダウンロードリンクを提供
- **哲学**: データの保全と GDPR 対応（必要時に一括削除できる）

## C. 追加アイデア（2026-06-29 追記）

### 表示・演出

#### C-1. 時刻連動プレースホルダー ✅ 実装済み（2026-06-29）

- **概要**: 投稿フォームのプレースホルダーテキストが JST 時間帯によって自動で変わる
- **実装規模**: 極小
- **実装**: `PostForm.tsx` に `timePlaceholder()` 関数を追加。`useMemo` でマウント時に一度だけ評価
  - 朝（5-10h）: 「今日の始まりに、何かありましたか」
  - 昼（10-17h）: 「起きたら消えてしまう本音、昼間だけの独り言をささやこう...」
  - 夕（17-22h）: 「今日が終わる前に、一つだけ残しておくとしたら」
  - 深夜（22-5h）: 「眠れない夜に、誰にも言えなかったことを」
- **哲学**: フォームを開いた瞬間に「今この時間にふさわしい言葉」への問いかけが始まる。書く前から時間と対話している

#### C-2. 消えゆく投稿の「残像」 ✅ 実装済み（2026-06-29）

- **概要**: 期限切れ投稿が即座に消えるのではなく、2.5 秒かけてフワッとぼけながら消えるアニメーション
- **実装規模**: 極小
- **実装**: `globals.css` に `@keyframes fade-away`（scale 縮小 + translateY 上昇 + blur 増加）を追加。`PostCard.tsx` で `onExpire` 発火時に `fading` state をセットし、`animate-fade-away` クラスを適用してから 2.5s 後に親コンポーネントへ通知
- **哲学**: 言葉が消える瞬間を「目撃できる」。即座の削除ではなく、消えていく過程そのものが体験になる

#### C-3. 今日の一文字（未実装）

- **概要**: 当日の全投稿テキストの中で最も多く使われた漢字 1 文字を、タイムライン背景にうっすら巨大テキストとして浮かべる
- **実装規模**: 小
- **実装**: API で漢字 1 文字単位の出現頻度を集計し、`/api/posts/featured-char` エンドポイントで返す。ページ背景レイヤーに `text-[20rem] opacity-[0.02]` で表示
- **哲学**: 今日という日の集合的な言葉の「核心」が背景に溶け込んでいる。意識しなくても感じる何か

#### C-4. 呼吸の間（未実装）

- **概要**: `/post/new` を開いた直後、textarea が 4〜5 秒間 disabled になり、ゆっくりした「……」アニメーションが流れる。時間が過ぎると自然にアクティブになる
- **実装規模**: 極小
- **実装**: `useState(false)` で `ready` フラグを持ち、`useEffect` で 5 秒後に `setReady(true)` するだけ
- **哲学**: 書く前に一呼吸置くことを強制する。衝動的な投稿をさらに一段抑える

#### C-5. 総文字数の墓標（未実装）

- **概要**: マイページに「これまでに N 文字の言葉を世界に放しました」を表示。投稿数ではなく、消えていった言葉の総量を静かに示す
- **実装規模**: 小
- **実装**: `SUM(LENGTH(content)) WHERE hidden_at <= NOW() AND deleted_at IS NULL AND user_id = :userId` クエリを追加。`getPostHourDistribution` と同じ場所に配置
- **哲学**: 「何件投稿したか」ではなく「どれだけの言葉を手放してきたか」という問いかけ

#### C-6. 同時刻の声（未実装）

- **概要**: 現在の JST 時と同じ時間帯に書かれた過去投稿に、ごく薄いハイライトをつける。「この時間に書かれた言葉」として時刻のエコーを感じる
- **実装規模**: 極小
- **実装**: クライアント側で `(new Date().getUTCHours() + 9) % 24` を取得し、`post.createdAt` の JST 時間と比較。一致するカードに `border-indigo-500/20` を追加するだけ
- **哲学**: 今この時間に同じ気持ちで書いた過去の誰かの声と共鳴する

## E. 採用しないもの（追記分）

| アイデア | 問題点 |
|---------|--------|
| 投稿の「バズり度」表示 | 閲覧数・到達数の可視化は承認欲求の数値化と同義 |
| 「おすすめ」アルゴリズム | エンゲージメント最大化のランキングは設計哲学に反する |
| 共有ボタン（アプリ内） | X シェアは既存。アプリ内シェアはフォロー関係前提となりやすい |
| 「あなたの投稿があと X 時間で消えます」通知 | 「自分の投稿が気になる」サイクルを強化する |
| 投稿の固定ピン（管理者以外） | 「目立たせる」行為そのものが排除対象 |

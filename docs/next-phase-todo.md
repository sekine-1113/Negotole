## 設計思想：ドーパミンを満たさない SNS

negotole は「ドーパミン報酬ループ」と「承認欲求の充足」を**意図的に設計から排除する**。

一般的な SNS がユーザーを引き留めるために使う仕掛け（いいね数・フォロワー数・通知バッジ・ストリーク・ランキング）は実装しない。ユーザーが「反応が気になって戻ってくる」状態を作ることは、このサービスの失敗を意味する。

### 排除するもの

| 仕掛け | 理由 |
|--------|------|
| いいね / リアクション | 承認の数値化。投稿を「評価される対象」にする |
| コメント / リプライ | 返答期待を生む。一期一会の体験を壊す |
| フォロー / フォロワー数 | 関係性の蓄積。「誰かに見てもらっている」依存を作る |
| 閲覧数・既読表示 | 「何人に届いたか」という承認指標 |
| 通知バッジ | 「戻らなければ」という強迫的誘引 |
| ストリーク・ランキング | ゲーミフィケーション。ポイントを「競う」ものにする |

### 許容するもの

- 投稿する行為そのもの（書いたら終わり）
- 時限消滅（投稿は必ず消える）
- 匿名の一期一会（誰が書いたかも、誰に届いたかも、永遠にわからない）
- ポイントシステム（「今日書ける」という小さな動機付け。ただしポイント蓄積・競争は避ける）

## 機能アイデア一覧（全20件）

### タイムライン体験

#### 1. ランダムタイムライン
- **概要**: 表示順を「新着順」ではなく「有効投稿のランダムサンプリング」に切り替えるモードを追加
- **実装規模**: 小（API に `?order=random` パラメータ追加、`ORDER BY RANDOM()` のみ）
- **哲学**: 「今投稿すれば上に来て目立つ」という計算が成立しなくなる。誰の投稿も等しく偶然に出会われる

#### 2. 読後消滅
- **概要**: スクロールして通過した投稿は次回開いたときに表示されない（localStorage で既読 ID を管理）
- **実装規模**: 小（フロントのみ。`Set<number>` を localStorage にシリアライズ）
- **哲学**: 「もう一度あの投稿を確認しよう」を不可能にする。出会いは一度きり

#### 3. 新着をサイレントに差し込む
- **概要**: 30秒ポーリングで新着投稿が来ても「新着 N 件」バッジを出さず、静かにタイムライン最上部に追加するだけにする
- **実装規模**: 極小（現状の実装から「件数表示」を消すだけ）
- **哲学**: 「何件溜まっているか」を気にさせない。確認しなければというプレッシャーをなくす

#### 4. 静寂表示
- **概要**: 現在アクティブな投稿が 0 件のとき、「今夜は誰もいない」「静かな夜です」などのテキストを表示する
- **実装規模**: 極小（既存の「まだ投稿がありません」テキストを置き換え）
- **哲学**: 誰もいない時間も体験の一部として肯定する。賑やかさへの期待を作らない

#### 5. 「今 N 件の言葉が生きています」バナー
- **概要**: タイムラインの上部に現在アクティブな投稿の総件数をひっそり表示する
- **実装規模**: 小（既存の `fetchPosts` レスポンスに `totalActive` を追加）
- **哲学**: 個別の投稿への注目ではなく、今この瞬間に存在する言葉の全体量を感じる。個人の承認ではなく集合的な息吹

#### 6. 深夜タイムライン
- **概要**: 22:00〜翌5:00 JST に投稿された投稿のみを表示するフィルター「夜の寝言」モード
- **実装規模**: 小（既存フィルター UI に `createdAt` 時間帯条件を追加）
- **哲学**: 昼の「パフォーマンス的な投稿」より、深夜の本音に近い声を選んで読める

### 投稿体験

#### 7. 投稿後の沈黙
- **概要**: 投稿完了後に「投稿しました」確認メッセージやプレビューを表示しない。フォームがリセットされるだけ
- **実装規模**: 極小（成功後の `router.push("/")` をフォームリセットのみに変更）
- **哲学**: 「ちゃんと届いたか確認したい」「自分の投稿をタイムラインで見つけたい」という衝動を生まない

#### 8. ブラインドポスト
- **概要**: タイムライン上で自分の投稿が他の投稿と全く同じスタイルで表示され、「これが私の投稿」という識別マークが一切ない
- **実装規模**: 小（現在の実装が既にそうかもしれないが、明示的に「本人識別禁止」として設計に書き込む）
- **哲学**: 自分の投稿を見つけて「どう思われているか確認する」ループを断つ

#### 9. ランダム表示期限
- **概要**: 投稿時に「おまかせ」を選ぶと、システムが 1h〜24h のいずれかをランダムに決定する
- **実装規模**: 極小（API で `duration: "random"` を受け取ったとき `VALID_DURATIONS` からランダム選択）
- **哲学**: 「6時間なら多くの人に届く」というコントロール欲求を手放させる。消えるタイミングも運命に委ねる

#### 10. タイムカプセル投稿
- **概要**: 投稿したが、指定時刻まで公開を遅らせる（例：8時間後にタイムラインに現れる）
- **実装規模**: 中（`post` テーブルに `published_at` カラム追加、タイムラインクエリに条件追加）
- **哲学**: 書いた直後に反応が来るか確認する行動が不可能になる。書く行為と公開の間に時間的断絶を入れる

#### 11. 1日1投稿モード
- **概要**: ユーザーが「今日はこれだけ書く」と決めて、1日1件に制限するオプション（ユーザー自身がオン/オフ）
- **実装規模**: 小（`user` テーブルに設定フラグ追加 or フロント側でのガード）
- **哲学**: 「もっと書けば誰かに届くかも」という量による承認獲得を自ら制限する

### 表示・演出

#### 12. カウントダウン非表示モード
- **概要**: CountdownTimer を非表示にするユーザー設定。投稿カードに「あと X 分」が出なくなる
- **実装規模**: 極小（設定フラグ or localStorage トグル、CountdownTimer を条件付きレンダリング）
- **哲学**: 「まだ読める時間がある」という計算をなくす。すべての投稿がいつ消えるかわからない状態で読む

#### 13. 投稿時刻の非表示
- **概要**: タイムライン上の投稿カードから投稿時刻を削除する
- **実装規模**: 極小（PostCard から `createdAt` 表示を削除）
- **哲学**: 「何時間前の投稿か」という情報が消えると、新鮮さ・鮮度による価値判断がなくなる

#### 14. 消えかけ投稿のゆらぎアニメーション
- **概要**: 残り時間が5分以内の投稿のテキストに微妙な揺らぎ（CSS keyframe animation）を加える
- **実装規模**: 小（CSS アニメーション定義 + `CountdownTimer` の `remaining` を PostCard に渡す）
- **哲学**: 「もうすぐ消える」を数値ではなく物理的な揺らぎで表現。儚さを身体的に感じさせる

#### 15. タイムラインの「息継ぎ」余白
- **概要**: 投稿カードとカードの間に、ランダムな高さの空白スペースを意図的に挿入する
- **実装規模**: 極小（各投稿に `Math.random()` で決まる `margin-bottom` を適用）
- **哲学**: 連続スクロールを促す「切れ目のない壁」をなくす。投稿と投稿の間に間を作る

#### 16. モノクロ表示オプション
- **概要**: タイムラインをグレースケールで表示するモードをユーザー設定に追加
- **実装規模**: 極小（CSS `filter: grayscale(1)` をトグル、localStorage 保存）
- **哲学**: 色の刺激を減らす。視覚的なドーパミン誘発要素（グラデーション・アクセントカラー）を消す

#### 17. 投稿の匿名グループ表示
- **概要**: 深夜など一定時間帯の投稿を「今夜、X人が孤独を書いた」「今夜、Y人が誰かへの感謝を書いた」のように感情カテゴリ別に集計して表示する（簡易キーワードマッチ）
- **実装規模**: 中（キーワード辞書 + 集計クエリ + 専用表示コンポーネント）
- **哲学**: 個人の投稿への注目ではなく、今夜の集合的な感情の地図を見る。承認の対象が「自分の投稿」から「人類の夜の気分」にシフト

### ゲーム性・ポイントの無力化

#### 18. ポイント数値の非表示オプション
- **概要**: ヘッダーのポイント残量を隠せるユーザー設定。「何pt」という数字を追いかけない人向け
- **実装規模**: 極小（localStorage トグル、ヘッダーの PointBadge を条件付きレンダリング）
- **哲学**: ポイントは「今日も書ける」という動機付けのためだけにある。数字を眺めて管理するものではない

#### 19. 天気連動ポイント
- **概要**: 毎日のデイリーポイント付与量が天気によって変わる（快晴=10pt、雨=12pt、雪=15pt）。Open-Meteo などの無料 API を使用
- **実装規模**: 中（サーバー側で天気 API 呼び出し、`grantDailyPoints` の引数を可変化）
- **哲学**: ポイントをゲーム的に「稼ぐ」ものではなく、世界の状態が偶然決めるものとして位置づける。雨の日のほうが書きやすいかもしれない、という体験

#### 20. 「今日書かなくていい」の明示
- **概要**: マイページに「今日ポイントを使い切らなくても、明日また付与されます」というテキストを常時表示する
- **実装規模**: 極小（静的テキストを UI に追加するだけ）
- **哲学**: デイリーポイントが「今日中に消費しなければ損」という焦りを生む可能性がある。それを言語で打ち消す

## 採用しないもの（設計思想に反するため）

| アイデア | 問題点 |
|---------|--------|
| 連続投稿ストリーク | 「今日も投稿しなければ」という強迫的誘引。ゲーミフィケーション |
| 匿名ポイント贈与 | 「誰かが自分の投稿を気に入ってくれた」という承認感が残る |
| 感情タグ + フィルター | 「共感されやすいタグで投稿しよう」という計算を生む |
| PWA プッシュ通知（ポイント付与以外） | 「戻らなければ」という強迫的誘引 |
